# BARTIKA JEANS — المتجر العام ونظام إدارة الفرع

منصة عربية RTL لمتجر BARTIKA JEANS تجمع بين الكتالوج العام وطلبات الشراء الإلكترونية ونظام نقاط البيع وإدارة الفرع. الهوية البصرية أخضر زمردي وذهبي، والعملة الجنيه المصري (EGP).

## فصل المشاريع

- مستودع GitHub: `zikrofficial-X/BARTIKA-JEANS`.
- قاعدة Supabase مخصصة لـ BARTIKA فقط: Project Ref `gnebcwgaahwowxwiqqlj`، منطقة Frankfurt (`eu-central-1`).
- قاعدة ZIKR ومستودعه لم يتم تعديلهما ضمن هذا العمل.
- Cloudinary الحالي هو الحساب المتصل المشترك، مع فصل ملفات BARTIKA داخل مجلدات `bartika-jeans/`. هذه مجلدات تنظيمية وليست Product Environment مستقلة.
- مستودع GitHub ما زال Public؛ يجب تحويله إلى Private قبل إدخال بيانات عملاء أو أسرار تشغيل.

## الوظائف الموجودة

- تسجيل الدخول وأدوار Admin / Manager / Seller مع صلاحيات Manager يمنحها Admin.
- لوحة إدارة، كتالوج منتجات، صور، أصناف متعددة المقاسات والألوان، SKU وباركود ومخزون.
- POS وفواتير بيع وخصومات ومدفوعات Cash / InstaPay / Visa / Mixed.
- ربط البيع بالوردية النقدية الصحيحة ومنع فتح أكثر من درج مفتوح للبائع نفسه.
- جرد ومشتريات متعددة البنود وحركات مخزون.
- دفتر منفصل لسداد الموردين وكشف حساب المورد.
- ملفات العملاء، حدود ائتمان، أرصدة مستحقة وتحصيل لاحق.
- استبدال ومرتجعات مرتبطة ببند الفاتورة الأصلية مع تسوية فرق السعر.
- تقارير مالية ولقطات تكلفة تاريخية؛ لا يعرض النظام الربح عندما تكون بيانات التكلفة ناقصة.
- متجر عام في `/shop` ولوحة إدارة الطلبات `/online-orders` للأدمن فقط.
- PWA وغلاف Offline؛ لا يدعم البيع أو مزامنة الفواتير دون اتصال.

## المتجر العام والطلبات

- يعرض الكتالوج المنتجات النشطة وسعر البيع والصورة والمقاسات والألوان المتاحة.
- مؤشر المخزون العام محدود إلى 0–5 ولا يكشف الكمية الفعلية للفرع.
- الطلب الإلكتروني يبدأ Unpaid مع حجز مؤقت للمقاسات، ولا يقوم الموقع بتحصيل InstaPay أو Visa آليًا.
- يجب على Admin التحقق من استلام النقدية أو التحويل ثم تسجيل التحصيل داخل لوحة الطلبات. لا يسمح النظام بتسليم الطلب قبل اكتمال دفع قيمته.
- بعد اكتمال التحصيل والتسليم تتحول الطلبات إلى فاتورة بيع مرتبطة بالطلب، مع تسجيل حركات المخزون ولقطة تكلفة الصنف إن كانت متاحة.
- رسوم التوصيل غير مضافة إلى إجمالي المنتجات في صفحة المتجر؛ يؤكدها المحل عند التواصل مع العميل.
- الطلب الذي لم يُسجل عليه أي تحصيل ينتهي حجزه بعد 24 ساعة ويُلغى ويُحرر المخزون عند تحديث الكتالوج أو إنشاء طلب جديد أو محاولة Admin تغيير حالة الطلب.
- الطلب ذو التحصيل الجزئي لا يُلغى آليًا ولا يُرد مبلغه آليًا؛ يتطلب معالجة Admin موثقة.
- الحد العام الحالي ثلاثة طلبات من رقم الهاتف في الساعة، ومفتاح idempotency يمنع تكرار الطلب عند إعادة الإرسال.

## قاعدة البيانات والترحيلات

الترحيلات `0001` حتى `0041` موجودة في `supabase/migrations`، ومطبقة على مشروع Supabase BARTIKA المستقل. آخر ترحيلات دورة المتجر هي:
- `0039`: لقطات الباركود والتكلفة، قفل مفتاح idempotency وحد الطلبات حسب الهاتف.
- `0040`: انتهاء الحجز غير المدفوع بعد 24 ساعة وتحرير المخزون.
- `0041`: تنفيذ تنظيف الحجوزات المنتهية قبل إنشاء طلب جديد وقبل تغيير Admin لحالة الطلب.

لا تعِد تطبيق أي ترحيل سبق تسجيله في `supabase_migrations.schema_migrations`. لا تستخدم أيًا من ترحيلات BARTIKA على مشروع ZIKR.

## التشغيل المحلي

1. استخدم Node.js 22 LTS وnpm.
2. نفّذ `npm install`.
3. انسخ `.env.example` إلى `.env.local`.
4. أدخل رابط ومفتاح Supabase العام لمشروع BARTIKA فقط.
5. أضف أسرار Cloudinary على الخادم فقط؛ لا تضع API Secret أو Supabase Service Role في `NEXT_PUBLIC_*`.
6. أنشئ مستخدم Admin الأول من Supabase Auth ثم عيّن له دور Admin من SQL Editor وفق `docs/PRODUCTION_SETUP_AR.md`.
7. شغّل `npm run dev`.

## بوابات ما قبل التشغيل التجاري

المشروع ليس معلنًا كجاهز للإطلاق التجاري بعد. ما زالت البنود التالية مطلوبة:
- تحويل مستودع GitHub إلى Private.
- إنشاء مشروع Vercel مستقل وربطه بالمستودع وفرع `main`؛ الحساب المتصل لم يكن يملك صلاحية إنشاء المشروع ضمن فريق Vercel الحالي عند آخر اختبار.
- إضافة متغيرات Supabase وCloudinary إلى بيئات Vercel.
- إنشاء/اختيار Cloudinary account أو Product Environment مستقل وتسليم مفاتيحه؛ المجلدات الحالية ليست بيئة مستقلة، كما لم تتوفر أسرار الرفع الحي.
- إنشاء أول Admin فعلي، وإدخال بيانات المنتجات والمخزون بعد الجرد.
- اختبار فعلي باستخدام حسابات Admin وManager وSeller وأجهزة المحل والطابعة والباركود.
- اختبار النسخ الاحتياطي والاستعادة، ومراجعة سياسة الاستبدال قانونيًا.
- لا يوجد بيع Offline آمن أو مزامنة معاملات في الإصدار الحالي.
