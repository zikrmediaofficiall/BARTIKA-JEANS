# BARTIKA JEANS — نظام إدارة محل ملابس رجالي

نظام نقاط بيع ومخزون ومتجر عام عربي RTL لمحل BARTIKA JEANS. الهوية: أخضر زمردي وذهبي. العملة: الجنيه المصري (EGP).

## الحالة
المستودع وقاعدة بيانات Supabase مخصصان لـ BARTIKA JEANS ومستقلان عن ZIKR. قاعدة البيانات الجديدة تحمل 13 ترحيلًا حتى الآن. لا توجد بيانات بيع أو مخزون فعلية أو حساب Admin أولي حتى الآن. لا يعتبر النظام جاهزًا للبيع التجاري قبل إعداد حساب Admin، وربط Cloudinary وVercel، واختبار دورة التشغيل الفعلية.

## الوحدات الحالية والمخططة
- تسجيل دخول وصلاحيات Admin / Manager / Seller.
- لوحة تحكم وتقارير.
- المنتجات، الأقسام، المقاسات، الألوان، SKU والباركود وصور المنتجات.
- POS وفواتير البيع والخصومات.
- وسائل الدفع: نقدي، InstaPay، Visa، والدفع المختلط والجزئي.
- الموردون والمشتريات والمخزون وحركاته.
- الجرد والتسويات.
- العملاء والأرصدة.
- الورديات والخزينة والمصروفات المرتبطة بدرج البائع أو الخزينة العامة.
- الاستبدال مع حفظ أثر العملية.
- سجل تدقيق.
- غلاف PWA وصفحة Offline آمنة؛ لا يتم اعتماد البيع دون اتصال في هذه النسخة.

## التقنية
- Next.js App Router + React + TypeScript
- Supabase Auth + PostgreSQL + RLS
- Cloudinary لصور المنتجات
- Tailwind CSS
- PWA / Service Worker
- GitHub Actions وVercel للنشر بعد منح صلاحية إنشاء المشروع وإكمال أسرار البيئة

## التشغيل المحلي
1. ثبّت Node.js 22 LTS وnpm.
2. شغّل `npm install`.
3. انسخ `.env.example` إلى `.env.local` وأدخل بيانات BARTIKA Supabase وCloudinary فقط.
4. استخدم قاعدة Supabase المنفصلة `gnebcwgaahwowxwiqqlj`. الترحيلات `0001` إلى `0013` مطبّقة بالفعل على هذه القاعدة؛ لا تُعد تطبيقها على مشروع ZIKR أو أي مشروع آخر.
5. أنشئ أول حساب من Supabase Auth، ثم امنحه دور Admin من SQL Editor بعد التحقق من بريد المالك. الخطوات التفصيلية في `docs/PRODUCTION_SETUP_AR.md`.
6. شغّل `npm run dev`.

## الأمان
- لا تضع Service Role Key في متغيرات NEXT_PUBLIC_* أو في المتصفح.
- تم تعطيل استدعاء الدوال الحساسة من anon، وسياسات RLS مفعلة لكل جداول public.
- سعر التكلفة والربح حقول إدارية. يجب ألا تُعرض للبائع ولا تُضمّن في استعلامات واجهته.
- لا تُحذف الفواتير أو حركات المخزون؛ استخدم مستندات عكسية مع سبب وسجل تدقيق.
- لا تضع بيانات العملاء أو الأسرار أو بيانات فعلية في Git.
- بيانات BARTIKA Supabase منفصلة بالكامل عن قاعدة ZIKR. مجلدات Cloudinary الحالية منفصلة تنظيميًا بمسار `bartika-jeans/` لكن البيئة الحالية المشتركة ليست حسابًا مستقلًا.
- المستودع عام في الوقت الحالي؛ حوّله إلى Private قبل إضافة أسرار أو بيانات تشغيل فعلية.

## التشغيل دون إنترنت
النسخة الحالية تخزن ملفات الغلاف الثابتة وصفحة Offline فقط، ولا تخزن بيانات البيع أو العملاء ولا تحفظ السلة بعد إعادة التحميل. اعتماد البيع يتطلب اتصالًا بالخادم حتى يتم التحقق ذريًا من المخزون والسعر والصلاحيات ومنع تكرار الفاتورة. لا يتم الادعاء بوجود بيع Offline آمن قبل بناء ومراجعة مزامنة idempotent كاملة.

## سياسة الاستبدال
يمكن عرض سياسة استبدال طوعي خلال 3 أيام للسلع السليمة، مع عدم الانتقاص من الحقوق القانونية الإلزامية للمستهلك المصري، خاصة السلع المعيبة والاستثناءات القانونية. راجع النص النهائي قانونيًا قبل طباعته.
