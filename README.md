# BARTIKA JEANS — نظام إدارة محل ملابس رجالي

نظام نقاط بيع ومخزون عربي RTL لمحل BARTIKA JEANS. الهوية: أخضر زمردي وذهبي. العملة: الجنيه المصري (EGP).

## الحالة
هذا المستودع هو بداية التنفيذ المستقل. يحتوي على تطبيق Next.js وطبقة Supabase وملف SQL لتأسيس قاعدة البيانات. لا توجد بيانات بيع أو مخزون افتراضية. لا يعتبر النظام جاهزًا للتشغيل التجاري قبل تطبيق migration، إعداد أسرار Supabase، إنشاء أول مدير، وتشغيل الاختبارات.

## الوحدات
- تسجيل دخول وصلاحيات Admin / Seller.
- لوحة تحكم وتقارير.
- المنتجات، الأقسام، المقاسات، الألوان، SKU والباركود.
- POS وفواتير البيع والخصومات.
- وسائل الدفع: نقدي، InstaPay، Visa، والدفع المختلط والجزئي.
- الموردون والمشتريات والمخزون وحركاته.
- الجرد والتسويات.
- العملاء والأرصدة.
- الورديات والخزينة والمصروفات.
- الاستبدال مع حفظ أثر العملية.
- سجل تدقيق.
- غلاف PWA وصفحة Offline آمنة؛ لا يتم اعتماد البيع دون اتصال في هذه النسخة.

## التقنية
- Next.js App Router + TypeScript
- Supabase Auth + PostgreSQL + RLS
- Tailwind CSS
- PWA / Service Worker

## التشغيل المحلي
1. ثبّت Node.js 22 LTS وnpm.
2. شغّل npm install
3. انسخ .env.example إلى .env.local وأدخل NEXT_PUBLIC_SUPABASE_URL وNEXT_PUBLIC_SUPABASE_ANON_KEY.
4. نفّذ ملفات supabase/migrations بالترتيب 0001 ثم 0002 ثم 0003 ثم 0004 على مشروع Supabase جديد (باستخدام Supabase CLI أو SQL Editor).
5. انشر Edge Function باسم admin-create-user باستخدام Supabase CLI. أنشئ حساب المدير الأول من Supabase Auth ثم امنحه دور admin يدويًا من SQL Editor بعد التحقق من هويته. لا توجد كلمة مرور افتراضية أو مفتاح سري داخل المستودع.
6. شغّل npm run dev

تشغيل الاختبارات: npm test

## الأمان
- لا تضع Service Role Key في متغيرات NEXT_PUBLIC_* أو في المتصفح.
- سياسات RLS هي خط الدفاع الأساسي. واجهة المستخدم ليست بديلًا عن صلاحيات قاعدة البيانات.
- سعر التكلفة والربح حقول إدارية. يجب ألا تُعرض للبائع ولا تُضمّن في استعلامات واجهته.
- لا تُحذف الفواتير أو حركات المخزون؛ استخدم مستندات عكسية مع سبب وسجل تدقيق.
- لا تضع بيانات العملاء أو الأسرار أو بيانات فعلية في Git.

## التشغيل دون إنترنت
النسخة الحالية تخزن ملفات الغلاف الثابتة وصفحة Offline فقط، ولا تخزن بيانات البيع أو العملاء ولا تحفظ السلة بعد إعادة التحميل. اعتماد البيع يتطلب اتصالًا بالخادم حتى يتم التحقق ذريًا من المخزون والسعر والصلاحيات ومنع تكرار الفاتورة. لا يتم الادعاء بوجود بيع Offline آمن قبل بناء ومراجعة مزامنة idempotent كاملة.
