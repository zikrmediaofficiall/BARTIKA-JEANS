# BARTIKA JEANS — متجر عام ونظام إدارة محل ملابس رجالي

منصة عربية RTL لمتجر BARTIKA JEANS تجمع بين الكتالوج العام وطلبات الشراء الإلكترونية ونظام إدارة الفرع. الهوية: أخضر زمردي وذهبي. العملة: الجنيه المصري (EGP).

## الحالة الحالية

- المستودع وقاعدة Supabase مخصصان لـ BARTIKA JEANS ومستقلان عن ZIKR.
- Supabase Project Ref: `gnebcwgaahwowxwiqqlj` — Frankfurt (`eu-central-1`).
- تم تنفيذ وحدات الإدارة والمبيعات والمخزون والعملاء والموردين والورديات والاستبدال والتقارير.
- تمت إضافة متجر عام في `/shop` وطلبات شراء بحجز مؤقت للمخزون، مع إدارة الطلبات في `/online-orders` للأدمن.
- الترحيلات حتى `0030` أُعدت/طُبقت على قاعدة BARTIKA. يجب مراجعة سجل migrations قبل أي إعادة تطبيق.
- لا توجد بيانات تشغيل حقيقية أو حساب Admin أولي مؤكّد في المشروع.
- المشروع غير جاهز للإطلاق التجاري قبل إكمال ربط Vercel وCloudinary واختبارات الأجهزة ودورة الطلب/التحصيل الفعلية.

## الوحدات

- تسجيل دخول وصلاحيات Admin / Manager / Seller.
- لوحة تحكم وتقارير.
- المنتجات، الأقسام، المقاسات، الألوان، SKU والباركود وصور المنتجات.
- POS وفواتير البيع والخصومات.
- وسائل الدفع داخل POS: نقدي، InstaPay، Visa، والدفع المختلط والجزئي.
- الموردون والمشتريات والمخزون وحركاته ودفتر سداد الموردين.
- الجرد والتسويات.
- العملاء وسجل الفواتير وحدود الائتمان والتحصيل.
- الورديات والخزينة والمصروفات المرتبطة بدرج البائع أو الخزينة العامة.
- الاستبدال مع حفظ أثر العملية وحماية صلاحيات البائع.
- سجل تدقيق.
- متجر عام وطلبات توصيل أو استلام، بحجز المخزون حتى التأكيد، ثم خصمه عند تسجيل التسليم.
- غلاف PWA وصفحة Offline آمنة؛ لا يتم اعتماد البيع دون اتصال في هذه النسخة.

## المتجر الإلكتروني: حدود الإصدار الحالي

- الكتالوج العام يعرض المنتجات النشطة وسعر البيع وصورة المنتج والمقاسات/الألوان المتاحة.
- كمية المخزون العامة محدودة إلى مؤشر توفر من 0 إلى 5، ولا تعرض كمية المخزون الداخلية.
- الطلبات الجديدة تُسجل كطلبات معلقة وتحجز الكمية مؤقتًا.
- الأدمن يستطيع تأكيد الطلب أو إلغاءه أو تسجيل تسليمه. الإلغاء يحرر الحجز، والتسليم يخصم الكمية ويسجل حركة مخزون.
- نموذج الطلب لا يجمع مدفوعات إلكترونية ولا يؤكد وصول InstaPay/Visa؛ لا يعتبر الطلب مدفوعًا حتى يتم التحقق من الدفع خارج الصفحة وتسجيله في النظام.
- الطلبات الإلكترونية حاليًا في دفتر مستقل، ولا تُحوّل تلقائيًا إلى فاتورة بيع POS أو تقارير الإيرادات. هذا تكامل مطلوب قبل اعتماد التقارير المالية النهائية.

## التقنية

- Next.js App Router + React + TypeScript
- Supabase Auth + PostgreSQL + RLS
- Cloudinary لصور المنتجات
- Tailwind CSS
- PWA / Service Worker
- GitHub Actions وVercel للنشر بعد منح صلاحية إنشاء المشروع وإكمال أسرار البيئة

## التشغيل المحلي

1. ثبّت Node.js 22 LTS وnpm.
2. شغّل `npm install`.
3. انسخ `.env.example` إلى `.env.local` وأدخل بيانات BARTIKA Supabase وCloudinary فقط.
4. استخدم قاعدة Supabase المنفصلة `gnebcwgaahwowxwiqqlj`. لا تطبق ترحيلات BARTIKA على مشروع ZIKR أو أي مشروع آخر.
5. أنشئ أول حساب من Supabase Auth، ثم امنحه دور Admin من SQL Editor بعد التحقق من بريد المالك. الخطوات في `docs/PRODUCTION_SETUP_AR.md`.
6. شغّل `npm run dev`.

## الأمان

- لا تضع Service Role Key في متغيرات NEXT_PUBLIC_* أو في المتصفح.
- جداول public محمية بسياسات RLS؛ دوال RPC الحساسة تمنع دور anon، باستثناء دوال الكتالوج العام وإنشاء طلب عام التي تعيد/تكتب بيانات محدودة ومتحققًا منها.
- سعر التكلفة والربح حقول إدارية؛ لا تعرضها للبائع أو للزائر.
- لا تحذف الفواتير أو حركات المخزون؛ استخدم مستندات عكسية مع سبب وسجل تدقيق.
- لا تضع بيانات العملاء أو الأسرار أو بيانات فعلية في Git.
- بيانات BARTIKA Supabase منفصلة عن قاعدة ZIKR. مجلدات Cloudinary الحالية منفصلة تنظيميًا بمسار `bartika-jeans/` لكنها ليست Product Environment أو حسابًا مستقلًا.
- المستودع عام حاليًا؛ حوّله إلى Private قبل إدخال بيانات تشغيل فعلية أو أسرار.

## التشغيل دون إنترنت

النسخة الحالية تخزن ملفات الغلاف الثابتة وصفحة Offline فقط. لا تخزن بيانات البيع أو العملاء ولا تحفظ السلة بعد إعادة التحميل. اعتماد البيع يتطلب اتصالًا بالخادم حتى يتم التحقق ذريًا من المخزون والسعر والصلاحيات ومنع تكرار الفاتورة. لا يوجد بيع Offline آمن أو مزامنة معاملات في هذا الإصدار.
